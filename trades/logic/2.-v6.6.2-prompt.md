# v6.6.2 — Prompt del sistema de predicciones (JS) para Cursor

> **Meta:** Generar **8–12** (o **6** si se fija `maxSignalsByRegime=6`) señales por cada **1000** velas de 15m, **sin ver al futuro**, consumiendo datos vía `getData`.

---

## Entrada de datos

- Llamada dinámica a:
  ```js
  const candles = await getData(symbol, quantity, fromISO?, previousCandles = 500, timeframe = '15m')
  ```
- `previousCandles` se usa para que el **feature window** (p. ej. 400–600 velas previas) esté siempre disponible.
- Si se requiere evaluar múltiples tramos, iterar en **ventanas de 1000** con **overlap** (recomendado `200`) usando `fromISO` para anclar el bloque, **sin reusar resultados de ventanas futuras**.

---

## Principios de no‑futuro (backtest honesto)

- Para la vela **i** de evaluación:
  - Features y filtros solo pueden usar `candles[0..i]`.
  - La **decisión** de señal se toma al **cierre** de la vela **i** (o con reglas explícitas de intrabar si las tienes simuladas).
  - SL/TP se calculan con ATR/estructura usando únicamente información ≤ **i**.
  - Validación de ejecución (ej.: break&retest) no puede consultar vela **i+1** antes de fijar la señal; solo se usa **después** para simular outcome, no para decidir.

## Parámetros esenciales (régimen “low” por defecto)

- `levelScoreMin=0.66`, `levelScoreMinSupport=0.64`
- `zoneWidthATR=0.28`, `minSpacingATR=0.40`, `minSpacingPct=0.18`
- `maxLevelsPerSide=12`, `lookbackLevels=180`, `avgBouncePctMin=0.15`

### Dirección (votos/score)
- `strategy='score'`
- thresholds: `low=0.42`, `mid=0.55`, `high=0.65`
- weights: `{ momentum:0.45, book:0.35, flow:0.20, vwapBonus:0.10 }`
- **Direction gating v6.6.2**: no bloqueante; penaliza y permite near‑miss con retorno inmediato a favor.

### Volumen (adaptativo)
- `ratioMinEffective_low=1.00` (clamp vol floor)
- fallback: `{ zScoreMin:0.20, percentileMin:40, closeBeyondPctMin:0.12 }`

### Expected Move
- caps: `low=0.90`, `mid=0.80`, `high=0.70`
- boost rule: `"closeBeyondPct >= 0.22% AND atrRatio >= 0.45"`

### RR / Targets
- `rrMin_low=1.00`, `tp2CapATR=2.0`
- Targets por ATR con fallback robusto.

### Space (opuesto)
- `skipIfOppositeZoneWithin=0.12`
- overrides: `alignment`, `pathClear`, `weakOpposite`, `atrRROk`

### Hygiene (v6.6.2)
- `tinySL`: `{ slPctMin:0.045, spreadMultMin:2.5, atrMultMin:0.20 }`
- `tickVol`: `{ percentileMin:40, zScoreMin:0.20 }`
- `tp1Min`: `{ pctMin:0.14, atrMultMin:0.45 }`
- `followThrough`: `{ maxRetracePct:0.65 }`
- `oneFaultTolerance`: `{ enabled:true, margin:0.08, eventScorePenalty:0.92 }`

### Frecuencia
- `cooldownPerLevel=20`, `cooldownGlobal=90`
- `maxSignalsPer1000=6` (ajusta a 8–12 si deseas más señales)

---

## Clustering y Emisión (v6.6.2)

1. **Ranking Top‑K**: `compositeScore = 0.6*event + 0.3*direction + 0.1*volumeQuality`
2. **Clustering diversidad**:
   - `diversityPriceRadius = max(0.12% del lastPrice, 0.35*ATR10)`
   - anti‑duplicados temporal (±5 velas) y por precio.
   - `postClusterCount` objetivo ≥ 6–8.
   - **Bypass** solo si `postClusterCount===0` (entonces usa `finalCandidates`).
3. **Balance por lado + cooldowns**: `maxPerSide=4`.
4. **Emitir** `N = min(maxSignalsPer1000, candidatos balanceados)`.

## Resultado requerido

- **Array de señales** (6–12 por cada 1000 velas) con:
  ```
  {
    id, dtISO, side, entry, sl, tp1, tp2?, rr,
    eventScore, directionScore, votes:{momentum,book,flow,vwap},
    targetsSource:'atr'|'struct',
    flags:[]
  }
  ```
- **PDF** por ventana (ver especificación en `pdf-spec`).
- **Snapshot JSON** con `version`, `regime`, `params_efectivos`, `stats` y listado de señales.

> **Importante:** Todas las decisiones (scores, filtros, targets) deben derivarse únicamente de datos ≤ vela evaluada. Prohibido el _look‑ahead_.
