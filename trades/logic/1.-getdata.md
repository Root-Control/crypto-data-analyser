# getData — Especificación (JS) para Cursor

**Firma**
```js
getData(symbol, quantity = 1000, fromISO = undefined, previousCandles = 0, timeframe = '15m')
```

**Objetivo**
Devolver **`quantity + previousCandles`** velas contiguas, en **orden ascendente**, sin fugas de futuro, usando **Redis** como caché y **Binance Futures** para backfill cuando falte historia.

---

## Claves de Redis (por símbolo y timeframe)

Usa nombres _namespaced_ para evitar colisiones:

- `{{SYMBOL}}:{{TIMEFRAME}}:DATA`  → arreglo JSON de velas (orden ascendente por `openTime`)
- `{{SYMBOL}}:{{TIMEFRAME}}:LEN`   → longitud del arreglo
- `{{SYMBOL}}:{{TIMEFRAME}}:FROM`  → ISO del primer `openTime` almacenado

> Ejemplo: `ETHUSDT:15m:DATA`

---

## Reglas generales

- **Ventana solicitada**
  - `need = quantity + previousCandles`
  - Si hay `fromISO`:
    - Alinear a inicio de vela (`timeframe`).
    - `start = fromISO - previousCandles * interval`
    - `end   = start + (need - 1) * interval`
  - Si NO hay `fromISO`: la ventana es las **últimas `need`** velas disponibles (más recientes).

- **Orden y deduplicado**
  - Siempre **orden ascendente** por `openTime`.
  - Deduplicar por `openTime` cuando se unan bloques.

- **Persistencia**
  - Tras cualquier backfill a Binance, **persistir** DATA, LEN y FROM actualizados en Redis.

- **Sin banderas especiales**
  - Si falta historia y Binance no tiene más (límite duro), devuelve lo **máximo posible** y deja **log** explicando el tope (no modificar el shape del retorno).

---

## Flujo con `fromISO` (modo anclado a fecha)

1. Calcular `start`/`end` como se indicó.
2. Verificar si la caché **cubre completamente** `[start, end]`:
   - **Sí** → devolver **slice exacto**.
   - **No** → determinar tramos faltantes (previos y/o posteriores) y **backfillear** desde Binance.

### Backfill hacia atrás (faltan previas)
- Encadenar requests con `endTime` decreciente.
- **Límite por request:** 1000 klines.
- En cada iteración:
  - `endTime = firstOpenTime - 1*interval`
  - Pedir bloque y **unir** al frente.
  - Parar al cubrir `start` o al agotar la historia del exchange.

### Backfill hacia adelante (faltan posteriores)
- Encadenar requests con `startTime` creciente.
- **Límite por request:** 1000 klines.
- En cada iteración:
  - `startTime = lastOpenTime + 1*interval`
  - Pedir bloque y **unir** al final.
  - Parar al cubrir `end` o al agotar la historia del exchange.

---

## Flujo sin `fromISO` (modo reciente)

1. `need = quantity + previousCandles`
2. Si Redis `LEN >= need` → devolver **últimas `need`**.
3. Si `LEN < need` → pedir hacia atrás a Binance hasta cubrir `need`, **unir + persistir**, y devolver **últimas `need`**.

---

## Formato de vela (cada elemento)
```js
{
  openTime:    number,        // ms
  openTimeISO: string,        // ISO del openTime
  open:  number,
  high:  number,
  low:   number,
  close: number,
  volume:number,
  closeTime:   number         // ms
}
```

---

## Logging mínimo (consola)
- Params: `symbol`, `timeframe`, `quantity`, `previousCandles`, `fromISO`
- Métricas: `need`, `cacheLEN`, `cacheFROM`, `binanceCalls`, `chunks[]`
- Nota de límite si el exchange no tiene más historia.

---

## Consideraciones de precisión
- Alinear `fromISO` al **inicio de vela** según `timeframe`.
- Unir bloques cuidando **no duplicar** bordes (`±1 interval` al encadenar).
- **No** mirar datOS posteriores a `end` bajo ninguna circunstancia para este fetch.
